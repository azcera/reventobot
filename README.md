# Revento Discord Bot

Бот для управления семейным сервером Revento (заявки, капты, архивы,
Telegram-интеграция).

## 🚀 Быстрый старт

1. `npm ci`
2. Заполните `.env`
3. `npm run build`
4. `npm start`

Сервер и дашборд написаны на TypeScript со строгой проверкой типов. `npm run typecheck` проверяет исходники, тесты и конфигурации. Сервер компилируется в `dist/`, общие браузерные модули — в `dist/browser/`; `npm start` запускает `dist/index.js`. После обновления исходников нужна повторная сборка. Тесты компилируются командой `npm run build:test`; `npm test` делает это автоматически.

Браузерные тесты используют Chromium (`npx playwright install chromium`). Можно использовать установленный Chrome: в PowerShell `$env:PLAYWRIGHT_CHANNEL='chrome'`, затем `npm run test:dashboard`.

## Дашборд

Интерфейс находится в `frontend/`: React, Tailwind и локально поставляемые
шрифты Inter / Noto Sans. `npm run build` собирает его в `public/dashboard/`.
После изменения интерфейса повторите сборку; бот обслуживает готовые файлы.
На Replit сборка выполняется при развёртывании автоматически.
Для разработки: запустите бот, затем `npm run dev:dashboard`.

Предпросмотр открывается только переключением «Редактировать / Предпросмотр».
Ввод текста не перерисовывает предпросмотр. Руководство по текущему разделу
открывается кнопкой книги в заголовке. Ошибки и подтверждения показываются
в модальных окнах. Отдельный раздел «Сообщения в Discord» и его API удалены;
загрузка и изменение контейнера остаются в конструкторе.

Discord-сессии сохраняются в PostgreSQL в таблице `dashboard_sessions`,
создаваемой автоматически. Перезапуск бота не требует повторного входа,
пока не истекли прежние 8 часов сессии. Хранятся хеш токена, профиль и CSRF;
OAuth access token не сохраняется. Права администратора проверяются заново
при каждом запросе. Выход и отзыв прав удаляют сессию. При откате версии
таблицу можно оставить: прежний код её не использует, данные бота не меняются.

Проверки: `npm test`, `npm run build`, `npm run test:dashboard`.
Для браузерных проверок один раз установите Chromium: `npx playwright install chromium`.
Они используют отдельный локальный сервер с тестовыми данными, без входа
в реальный Discord и без изменения сообщений или настроек рабочего бота.

## Предустановки ручных сборов

В дашборде откройте «Сборы», добавьте предустановку и задайте имя slash-команды
без `/`, цель, текстовый канал и лимит подтверждённых участников.
Записавшиеся ожидают подтверждения модератора. Необязательная роль доступа разрешает
вызов команды дополнительно к администраторам и `ADMIN_ROLES`; без неё командой
пользуются только администраторы и модераторы бота.
После «Сохранить сборы» команда появляется в Discord и открывает форму с одним
полем даты и времени: `18:00` (сегодня) или `29.08.2026 18:00`, по Москве.
Канал, цель и лимит берутся из предустановки. Изменить время опубликованной реги
можно прежней кнопкой. Удаление предустановки удаляет её команду, уже опубликованные
реги продолжают работать. Обычная `/capt` по-прежнему запрашивает время, цель и
количество. Автокапт не использует предустановки.

Настройки сохраняются с аудитом и проверкой версии в `dashboard_state`;
`capture_preset_commands` хранит имена команд для синхронизации после перезапуска.

## Расписание Majestic RP

Команда `!schedule` публикует расписание в текущем канале и обновляет сообщение
каждые 15 минут. Ближайшие события рассчитываются локально по МСК, без запросов
к Mitsuki Hub. Кнопка создания группа отклоняет уже начавшиеся события.
Опубликованные сообщения сохраняются в базе и обновляются после перезапуска.

Поставки создаются без времени; код группы необязателен. Кнопка Острова
(вт, чт, вс) или ФЗ (пн, ср, пт, сб) выбирается по текущему дню МСК.
Укажите время проверки явки: сбор назначается на 5 минут раньше. Проверка явки
доступна в 16:00–19:00 и 20:00–23:00 соответствующего дня; вне этих интервалов
расписание показывает «Нападение запрещено». Общий текст всех групп меняется
в дашборде: «Группа → Сообщение группы для всех мероприятий».

У обычных регистраций кнопки вступления, выхода и изменения времени перестают
работать через час после начала. Сообщения проверяются после запуска и каждые
30 секунд. API-регистрации каптов сохраняют более раннее закрытие за 3 минуты
до начала. Для старых регистраций без сохранённого канала бот ищет сообщение
в текущем канале регистраций и каналах предустановок.

`GET /api/schedule` возвращает `project`, `timezone`, `generatedAt`, `events`
и отсортированный список `upcoming` с датами ближайших событий (`timestamp`
в миллисекундах Unix). API использует обычную авторизацию дашборда.
Основные времена берутся из `src/features/capture/groupOptions.ts`, специальные
интервалы — из `src/config/eventSchedule.ts`. При изменении игровых расписаний
обновите эти данные и перезапустите бота.

## Предпросмотр синхронизации Majestic

Скопируйте `.env.majestic.example` в `.env.majestic.local` и заполните
`MAJESTIC_SESSION_ID` значением `sessionId` из Cookie запроса состава семьи.
Оно используется и для Cookie, и для заголовка `x-session`. Файл исключён
из Git. `node dist/scripts/check-majestic.js` проверяет получение полного состава.

При настроенных `TG_NOTIFICATION_BOT_TOKEN` и `TG_NOTIFICATION_CHAT_ID` бот каждый день
в 22:00 по Москве запрашивает новое значение sessionId в личном чате. Отправьте само
значение или JSON вида `{"state":{"sessionId":"..."},"version":0}`: бот извлечёт
sessionId, проверит его через Majestic и применит без перезапуска. До успешной
проверки и сохранения используется прежняя сессия. Запросить замену вручную можно
командой `/session`. Новое значение хранится в PostgreSQL, в таблице
`majestic_session`, и имеет приоритет над `MAJESTIC_SESSION_ID` после перезапуска
и перепубликации. При первом запуске старый файл `.majestic-session`, если он
есть, переносится в базу; после этого файл больше не используется ботом.
Для приёма сообщений нужны работающая база данных и Telegram polling без webhook.

`node dist/scripts/preview-majestic.js` читает состав Majestic и участников Discord
(использует `TOKEN` и `GUILD_ID` из `.env`, требуется Server Members Intent).
Бот при этом не запускает свои обычные обработчики. Ники и роли не изменяются.
Отчёт `.majestic-preview.json` исключён из Git; статусы: `change` — план изменения,
`unchanged` — без изменений, `skipped` — нет сопоставления, `conflict` — ручной разбор,
`blocked` — недостаточно прав или роль недоступна.

Сопоставление пока выполняется по static из текущего ника, без подтверждения
владения персонажем. Формат: `[префикс] Имя | static / необязательный текст`.
Имя берётся из Majestic без фамилии; префикс и текст сохраняются. Ник длиннее
32 символов, несколько участников с одним static или несколько Tier-ролей
отмечаются как конфликт. Отсутствие персонажа в составе не снимает роли.

Список игровых рангов и ID ролей задан в `src/features/majestic/syncPreview.ts`.
Обычно из этого списка остаётся одна роль. Исключение: игровой ранг Dep, High
или Recruit сочетается с одной уже выданной Tier 1/2/3. Админская роль выбирается
по игровому рангу; другие ранговые роли снимаются. Несколько Tier-ролей остаются
конфликтом до ручного выбора. Уже выданная Tier 1/2/3 сохраняется
независимо от игрового ранга. Если
Tier-роли нет, выбирается роль игрового ранга. Leader и Own.dep не назначают
ранговую роль; при нескольких обычных ролях для них требуется ручной выбор.
Прочие роли Discord не затрагиваются. Скрипт остаётся только предпросмотром.

В дашборде откройте «Majestic — синхронизация». Нажмите «Получить предпросмотр»,
проверьте предложения и отметьте участников для применения. Можно начать с
одного участника. Ручные изменения выполняются кнопкой «Применить выбранные».
Автосинхронизация отдельно обновляет ники и ранговые роли по расписанию. Прогресс и результат обновляются автоматически, кнопка
«Остановить» прекращает следующие изменения без отката уже выполненных.

В карточке участника можно подтвердить или исправить постоянную привязку
Discord ID к static, исключить аккаунт из синхронизации и вернуть обратно,
а при нескольких Tier-ролях выбрать одну уже выданную роль для сохранения.
При дублирующихся static исправьте привязки или исключите лишний аккаунт.
«Сбросить решение» возвращает сопоставление по текущему нику. После изменения
решений нужен новый предпросмотр. Ники длиннее лимита исправляются вручную
в Discord. Префикс администратора при смене соответствующих ролей рассчитывается
по итоговым ролям и настройке ADMIN_ROLES; остальной текст сохраняется.

Решения, последний предпросмотр и результат операции хранятся в новой таблице
`majestic_sync_state`, она создаётся автоматически. Действия администратора и
изменения участников записываются в существующий журнал дашборда. Требуются
права бота Manage Nicknames, Manage Roles и подходящая иерархия. Запускайте один
экземпляр бота, как и для остальных настроек дашборда. После перезапуска
прерванная операция не продолжается автоматически: получите новый предпросмотр.

Предпросмотр действителен 15 минут и используется один раз. Перед применением
состав и Discord перечитываются; устаревший план отклоняется. Непосредственно
перед изменением участника дополнительно проверяются его ник и роли. Операция
не является общей транзакцией Discord: при ошибке уже выполненные изменения
сохраняются, результат может требовать ручной проверки и нового предпросмотра.

Массовые изменения выполняются последовательно, без ограничения в 100 участников.
Ожидание REST-лимитов и повторы временных ошибок выполняет discord.js.
Ошибка чтения или изменения отдельного участника записывается в его результат,
остальные участники продолжают обрабатываться. Итог «Завершено с ошибками» означает,
что список обработан, но отдельные изменения не подтверждены: проверьте их в Discord
и получите новый предпросмотр для повтора. Прогресс сохраняется после каждого
участника. Ошибка базы останавливает операцию; после перезапуска бота нужен новый
предпросмотр. Такое же продолжение после ошибки участника действует для автосинхронизации.

На Replit задайте MAJESTIC_SESSION_ID, MAJESTIC_SERVER=RU8
и MAJESTIC_CHARACTER_ID=289229 через Secrets и перезапустите бот. Значения сессии
в интерфейс и журнал не передаются. После публикации один раз отправьте актуальную
сессию через `/session` в Telegram: она сохранится в базе и будет восстанавливаться
при последующих публикациях с той же базой. Значение в Secrets служит начальным
резервом, пока в базе нет сессии. Истёкшую сессию обновляйте через `/session`.

Автосинхронизация **ников и ранговых ролей** включена по умолчанию: проверка
после запуска бота и затем каждые 10 минут после завершения предыдущей.
Выключатель в настройках: «Автосинхронизация ников и рангов Majestic каждые 10 минут».
Для совместимости ключ `MAJESTIC_AUTO_NICKNAMES` сохранён; существующее значение
настройки продолжает действовать, но теперь включает обновление ролей.

Если static однозначно читается из серверного ника и найден в составе семьи,
Discord ID автоматически получает постоянную привязку к static. Нажимать
«Подтвердить привязку» не нужно, в том числе для новых участников и участников
без изменений ника. Уже сохранённые привязки сохраняются независимо от текста
ника; вручную их можно исправить или сбросить. Дубли static, исключённые аккаунты
и static вне состава автоматически не привязываются.

Используются текущие правила ручного предпросмотра: имя без фамилии, сохранение
текста после `/`, ранговые роли по игре, сохранение одной Tier-роли и посторонних
ролей. Админский префикс пересчитывается по итоговым ролям. Leader/Own.dep не
назначают игровую ранговую роль. Конфликты рангов, несколько Tier-ролей,
слишком длинные ники и недостаточные права требуют ручного разбора; ошибочные
строки не мешают обработке остальных участников.

Теги берутся из «Префиксы ролей в никах» в дашборде. Допустимы `[Dep]`,
`TAG >` и другие варианты без `|` и переноса строки. Бот добавляет пробел
после тега; итоговый формат — `тег Nick | Static`. Кнопка обновления ников
заменяет прежний тег, а синхронизация Majestic использует настройки тегов
даже при обновлении только ников.

Автоматическая проверка не запускается параллельно с ручной операцией.
Её результат виден в разделе Majestic, изменения пишутся в журнал. Если привязки, ники или роли
изменились, ранее открытый ручной предпросмотр нужно обновить. При ошибке
сессии/ответа API изменения не выполняются; при ошибке Discord уже выполненные
изменения сохраняются. Для остановки следующих проверок выключите настройку.
Расписание действует круглосуточно и не связано с окном опроса API каптов.

Опция `MAJESTIC_AUTO_KICK` управляет только исключением из Discord по новым
событиям `logs.family_log.uninviteFrom` из журнала семьи Majestic (та же сессия).
Сверка состава с Discord формирует список для ручных действий и сама никого не кикает.
Для автокика бот должен ранее увидеть однозначно привязанный static в семье;
уволенный определяется по `account.id`, а не по `actionBy.id`. Событие должно быть
позже последнего подтверждения членства и начала отслеживания. При первом запуске
новой системы старые привязки и старые события не служат основанием для кика.
Перед каждым автокиком журнал, состав и Discord-участник проверяются повторно.
Возвращение в семью, повторный вход в Discord, конфликт static, защищённая роль,
активная заявка или ошибка получения данных блокируют автокик. Основание пишется в аудит.
Проверяются последние 50 увольнений: пропущенное за длительный простой событие
не заменяется предположением по отсутствию в составе и требует ручного разбора.

## Капты из Telegram

Объявления каптов снова поступают из уведомлений MajesticRolePlayBot в Telegram.
Для пользовательской Telegram-сессии нужны `TG_API_ID`, `TG_API_HASH` и
`TG_SESSION`; при отсутствии сессии потребуется вход по QR-коду. В дашборде
выберите «Канал объявлений каптов из Telegram» (`CAPT_INFO_CHANNEL_ID`) и
«Канал регистрации на капт» (`PLUS_CHANNEL_ID`). Кнопка объявления создаёт
набор с противником и временем из соответствующего уведомления.

## Капты из Majestic Family Wars API (отключено)

Описанный ниже API-режим сохранён в коде, но не запускается. Старые кнопки
API-регистрации и команда `!testcapt` временно недоступны.

В API-режиме объявления каптов читались из
`https://api.majestic-files.net/v1/ext/family-wars/RU8`, Telegram-парсинг каптов
был отключён. Telegram-рассылка и личные уведомления работают отдельно.
Запрос выполняется ежедневно в 15:00:05–21:30:05 по Москве, каждую минуту
на пятой секунде, без параллельных запросов. После перезапуска следующий запрос
попадает на ближайшее подходящее время; ночью API не опрашивается.

В настройках дашборда выберите «Канал объявлений каптов из Majestic API»
(`CAPT_INFO_CHANNEL_ID`) и «Канал регистрации на капт» (`PLUS_CHANNEL_ID`).
Боту нужны View Channel, Send Messages и Read Message History в обоих каналах,
а для первоначального оповещения — право упоминать @everyone. Фильтр семьи:
`defendersId === 1698` или `attackersId === 1698`. Данные сохраняются в таблицу
`family_wars`, которая создаётся автоматически. Новые объявления публикуются
только для будущих каптов текущего дня МСК, не отмеченных как завершённые или
нейтральные. Завершённая история при запуске не рассылается.

Пример настроек фильтра — `.env.family-wars.example` (перенесите значения в
`.env` или Replit Secrets, отдельный example-файл автоматически не загружается).
Пока подтверждён только статус `finished`. Любой другой статус допускается без
списка разрешённых названий; дополните `FAMILY_WARS_CLOSED_STATUSES`, когда
станут известны реальные названия отмены/завершения. Предварительный фильтр
нейтральных клеток: ID `0,-1` и точные названия из `FAMILY_WARS_NEUTRAL_NAMES`
без учёта регистра. Эти признаки предположительные: нейтраль с другим ID и
названием не будет распознана, пока вы не дополните настройки. После изменения
переменных перезапустите бот.

Для доступа обязателен `FAMILY_WARS_API_KEY` в `.env` или Replit Secrets.
Бот передаёт его в заголовке `x-api-key` только на фиксированный API-адрес;
перенаправления запрещены. После заполнения перезапустите бот. Без ключа запрос
не отправляется. При ошибке доступа данные сохраняются, отправка новых каптов
ждёт успешного опроса. Не помещайте настоящий ключ в example-файл или журнал.

Кнопка объявления создаёт одну связанную регистрацию. Повторное нажатие
возвращает её ссылку. 🎮 означает присутствие static в `players["1698"]` без
подтверждения в Discord, ✅ — присутствие в игре и нажатие «Принять»,
⏳ — нажатие «Принять» в ожидании записи в игре. Игроки из API отображаются даже
без записи в Discord. Для сопоставления используются подтверждённые привязки
из раздела Majestic, затем static из ника. При неоднозначном совпадении
показывается игровое имя со static и предупреждение, без выбора случайного
Discord-аккаунта. Сортировка по времени записи и по роли с временем сохраняется;
для игроков только из API используется время первого обнаружения.

Время берётся из `startAt` и обновляется автоматически; ручных кнопок изменения
времени и одобрения в API-регистрациях нет. Ручные наборы сохраняют прежнюю
логику. Удалённый из игрового состава игрок возвращается в ожидание, если он
ранее записывался. «Выйти» убирает ожидание, а для игрока в составе отмечает
отказ в Discord: состав API эта кнопка не меняет.

Регистрация закрывается за 3 минуты до последнего полученного `startAt`;
при переносе до закрытия таймер пересчитывается. После закрытия кнопки
отключаются, время и состав регистрации фиксируются; повторно она не открывается.
Таймер восстанавливается после перезапуска и работает независимо от опроса API.
При недоступности API используется последнее известное время начала.
Объявление оформлено как прежнее уведомление из Telegram, с баннером капта.
Оно обновляет время, карту, статус и результат до получения `finished`, затем
фиксируется окончательно. Если карта не указана, выводится «Неопределена».
Результат определяется по `winner` (с резервными `winnerId` и `winnerFamilyId`):
«🏆 Победа», «❌ Поражение» или «❔ Неопределено». Расчёт оставшихся игроков убран.
Для `finished` внизу показываются MVP нашей семьи по `damage` и `kills`:
только Discord при однозначной привязке по статику, иначе игровой ник и статик;
рядом — значение урона или киллов.
При равных показателях выбирается первый игрок в ответе API;
при отсутствии статистики MVP не определён.

Для администраторов: `!testcapt info` показывает плашку последнего `finished`
капта нашей семьи с исходным временем, картой, результатом и MVP, без
упоминания всех и создания рабочей регистрации. `!testcapt info attack` выбирает
последний завершённый капт из API, где наша семья была атакующей.
`!testcapt` создаёт отдельную
тестовую регистрацию со снимком состава последнего завершённого капта;
её кнопки доступны до конца текущего дня МСК.

Если `players["1698"]` отсутствует или имеет неизвестный формат, последний
известный состав сохраняется с предупреждением. Только явно переданный массив
`[]` очищает состав. По имеющемуся примеру нельзя подтвердить, публикуется ли
состав до боя: если API выдаёт его только после завершения, до этого момента
будет доступно лишь ожидание. Ошибка API или исчезновение записи из выдачи
не очищают регистрацию. В сообщении указан момент получения состава.

При неоднозначном результате отправки бот ищет своё сообщение по кнопке среди
100 последних сообщений канала. Если подтвердить отправку не удалось, повтор
останавливается с сообщением в журнале `[FamilyWars]`, чтобы не создавать дубль.
Если сообщение действительно не было отправлено, после ручной проверки можно
сбросить соответствующее поле `announcement_state` или `registration_state`
из `sending` в `NULL` в таблице `family_wars`. Не сбрасывайте его, если сообщение
существует: сначала восстановите ID сообщения. Запускайте один экземпляр бота.

## Дашборд и вход через Discord

Откройте `http://localhost:3000` после запуска бота. Дашборд содержит обзор,
конструктор v2, шаблоны, редактор опубликованных сообщений, настройки и историю.
Существующие API отправки/редактирования теперь требуют авторизованную сессию.

1. В приложении бота в [Discord Developer Portal](https://discord.com/developers/applications)
   откройте OAuth2 и добавьте Redirect URI:
   `http://localhost:3000/auth/discord/callback` (для внешнего адреса замените начало).
2. Добавьте в окружение `CLIENT_ID`, `DISCORD_CLIENT_SECRET`, `GUILD_ID`,
   `DASHBOARD_URL` без завершающего `/`. Пример — в `.env.example`.
   Используйте существующий `CLIENT_ID` приложения бота. Если OAuth2 Client Secret
   уже хранится как `CLIENT_SECRET`, код использует его без дублирования.
3. Укажите `DATABASE_URL` или существующую `SUPABASE_URL`; нужны права создания таблиц.
4. Запустите `npm start` и войдите через Discord. Доступ имеют владелец и
   участники с правом **Administrator** на сервере `GUILD_ID`. `Manage Server`
   и модераторские роли бота сами по себе доступ не дают.
5. Чтобы сузить круг администраторов, задайте `DASHBOARD_ALLOWED_USER_IDS`:
   Discord ID пользователей через запятую. Этот фильтр действует и для владельца.

Для внешнего доступа используйте HTTPS и соответствующий Redirect URI. HTTP
разрешён только для localhost/127.0.0.1. При изменении порта обновите `PORT`,
`DASHBOARD_URL` и Redirect URI. Секреты в интерфейс не передаются. Права участника
и роли повторно запрашиваются у Discord при каждом API-запросе; при недоступном
Discord доступ закрывается. Cookie HttpOnly/SameSite, проверка Origin и CSRF-токен
защищают операции записи. Сессия живёт 8 часов и завершается при перезапуске.

Для текущего адреса Replit задайте в Secrets
`DASHBOARD_URL=https://revento-bot--azcera.replit.app`, а в Discord OAuth2 Redirects —
`https://revento-bot--azcera.replit.app/auth/discord/callback`.
OAuth2 Client Secret — отдельный секрет, это не токен бота `TOKEN` и не публичный ключ.
Если сохранённого Client Secret нет, получите новый через «Сбросить секретный ключ»
в OAuth2 и сохраните его в Replit Secrets как `DISCORD_CLIENT_SECRET`.
Сброс заменяет прежний OAuth2-секрет: другие использующие его сервисы потребуют
обновления. Не записывайте секрет в исходники и не отправляйте его в чат.

Шаблоны и настройки сохраняются в PostgreSQL (`dashboard_state`), изменения —
в `dashboard_audit`. Параллельное сохранение со старой ревизией отклоняется:
обновите данные и повторите правки. Запускайте один экземпляр бота: настройки
после загрузки читаются из памяти процесса. Каналы, роли и переключатели дашборда
читаются только из БД (для переключателей сохраняются значения по умолчанию).
При первом запуске этой версии непустые значения этих настроек из `.env`
однократно переносятся в БД, без перезаписи уже сохранённых значений, включая
намеренно пустые. Перенос и его отметка фиксируются одной транзакцией;
в истории появляется запись `settings.migrate` со списком импортированных ключей.
После успешного запуска и проверки настроек в дашборде можно удалить из окружения:
`AUTO_ROLE`, `PLUS_CHANNEL_ID`, `PARENT_CHANNEL_ID`, `PING_CHANNEL_ID`,
`INVITE_CATEGORY_ID`, `CAPT_INFO_CHANNEL_ID`, `ADMIN_ROLES`,
`FAMILY_ADDITIONAL_ROLES`, `LOG_CHANNEL_ID`, `ARCHIVE_GROUP_ROLES`,
`ARCHIVE_SETTINGS_CHANNEL`, `PRIORITY_ROLES`, `DISCORD_NOTIFICATION_CHANNEL_IDS`
и переключатели из раздела настроек. Последующие изменения этих ключей в env
игнорируются. Токены, параметры подключений, OAuth2 и интеграций остаются в env.
В разделе «Настройки» показаны пустые значения в БД: нажмите название,
выберите канал или роль и сохраните. Для неиспользуемых функций поля можно
оставить пустыми. При неполных настройках архивов обновление их списков
пропускается без изменения существующих сообщений.

Во вкладке «Шаблоны» можно один раз привязать постоянные сообщения: правила,
приглашение, систему повышения и памятку рекрута. Привязки хранятся в PostgreSQL.
Новые сообщения команд `!rules` и `!invite` привязываются автоматически. Для уже
опубликованных сообщений укажите ссылку один раз; поля системы повышения и памятки
импортируются из самого сообщения. Сохранение и сброс шаблона обновляют привязанное
сообщение в Discord. При ошибке Discord шаблон сохраняется, интерфейс сообщает о
неудаче; кнопка «Обновить в Discord» повторяет отправку без изменения ревизии.
Пустая ссылка удаляет привязку. Редактировать можно только контейнеры этого бота
на настроенном сервере. Остальные шаблоны меняют следующие отправки и обновления ботом. Переменные шаблонов
обязательны: их значения формируются ботом. Редактор по ссылке меняет только
указанную публикацию этого бота, сохраняя вложения, структуру и идентификаторы
кнопок. Доступны текст, подписи кнопок, ссылки Link-кнопок без настройки цвета контейнера.
Динамические списки каптов и архивов нужно менять через шаблоны, иначе очередное
обновление ботом перезапишет правки. Формы ввода заявок и логика кнопок не меняются.
Изображения задаются в шаблонах тегом `<img src="https://example.com/image.png" />`.
Для объявлений каптов и расписания доступны отдельные поля изображения; пустое поле
отключает его. В правилах и приглашении добавьте или удалите тег в тексте документа.
В старых сохранённых шаблонах ссылки `attachment://` на локальные файлы приглашения
нужно заменить общедоступными HTTPS-ссылками; существующие вложения привязанных
сообщений можно продолжать использовать при их обновлении.
Превью шаблонов и сообщений использует общий с конструктором Markdown: заголовки, жирный текст, курсив, подчёркивание, код и ссылки. Переменные заменяются примерами; это приблизительный вид Discord. Новые и обновляемые из дашборда контейнеры публикуются без цветной полосы.

Массовую Telegram-рассылку можно поставить на паузу: новые сообщения в это время
не попадают в очередь, накопленные задания ждут включения доставки. Уже выполняющийся
запрос может завершиться. Подписки и обработка `/start`/`/stop` продолжают работать.
Для включения этой интеграции нужен существующий `TG_NOTIFICATION_BOT_TOKEN`;
канал личных уведомлений не включается в массовую рассылку.

Проверка без внешних подключений: `npm test`.
Реальные OAuth2, права Discord и PostgreSQL проверяйте с настроенным окружением.

## Пользовательские шаблоны сообщений

На странице «Шаблоны» нажмите «Новый шаблон», задайте название и напишите
сообщение в Markdown. Сохраните шаблон, затем в настройках постоянного сообщения
выберите канал и нажмите «Опубликовать / обновить». Последующие сохранения
автоматически обновляют привязанное сообщение в Discord, в том числе после
перезапуска бота. При смене канала прежняя копия остаётся без синхронизации.
Можно также привязать существующее сообщение этого бота по ссылке.
Пользовательский шаблон можно удалить кнопкой корзины рядом с сохранением.
Опубликованное сообщение останется в Discord, а его синхронизация прекратится.

Поддерживаются текст, разделители, изображения и секции с кнопкой-ссылкой.
Удаление тега img из документа убирает изображение. Объявление капта
редактируется одним Markdown-документом, включая картинку и текст с переменными.
Для расписания доступна только ссылка на картинку; текст и кнопки задаёт бот.

Чтобы получать сообщения из Discord от Telegram-бота в личный чат:

1. Создайте бота через [@BotFather](https://t.me/BotFather) и сохраните токен.
2. Откройте созданного бота в Telegram и нажмите «Начать».
3. Откройте `https://api.telegram.org/bot<ТОКЕН>/getUpdates` и найдите
   число в поле `message.chat.id`. Не передавайте токен другим людям.
4. Укажите в `.env` и перезапустите приложение:

```env
DISCORD_NOTIFICATION_CHANNEL_ID=ID_канала_Discord
TG_NOTIFICATION_BOT_TOKEN=токен_бота
TG_NOTIFICATION_CHAT_ID=ID_личного_чата
```

Бот должен видеть канал и иметь доступ к содержимому сообщений. Пересылаются
текст, подписи типов вложений и имя автора; сообщения ботов пропускаются.
Уведомления должны быть включены в настройках чата с Telegram-ботом.

## Рассылка из Discord подписчикам Telegram

Старая пересылка `DISCORD_NOTIFICATION_CHANNEL_ID → TG_NOTIFICATION_CHAT_ID`
продолжает работать отдельно, с прежней фильтрацией сообщений ботов.
Для массовой рассылки добавьте:

```env
DISCORD_NOTIFICATION_CHANNEL_IDS=ID_первого_канала,ID_второго_канала
TG_NOTIFICATION_BOT_TOKEN=токен_существующего_бота
```

Нужны Node.js 20.3+ и доступная PostgreSQL через существующую переменную
`SUPABASE_URL` или `DATABASE_URL`, с правом создания таблиц.
После перезапуска таблицы подписчиков, очереди, offset и дублей создаются автоматически.
Каждый получатель должен отправить `/start` в личном чате с ботом;
`/stop` отключает рассылку и удаляет его ожидающие отправки.
Если пользователь запускал бота до появления этой функции, нужно повторить `/start`.
Бот должен видеть выбранные Discord-каналы; Message Content Intent должен быть
включён в Discord Developer Portal (в коде он уже включён).

Из списка массовой рассылки всегда исключается `DISCORD_NOTIFICATION_CHANNEL_ID`,
даже если он указан случайно. Остальные каналы пересылаются всем активным подписчикам,
включая сообщения Discord-ботов и webhook. Пересылаются текст, текстовые компоненты,
embed и подписи `[Изображение]`, `[Видео]`, `[Аудио]`, `[Файл]`, `[Опрос]`,
`[Стикер]` вместо ссылок на вложения. Это же правило действует для приватной пересылки.
Длинные уведомления разбиваются на части.
Одинаковое содержимое во всех выбранных каналах подавляется на 5 минут,
независимо от автора и канала. Вложения сравниваются по ссылкам: одинаковые файлы,
загруженные заново с другими URL, могут считаться разными сообщениями.

Запускайте только один экземпляр приложения с этим токеном и без Telegram webhook:
получение команд выполняется через `getUpdates`. При активном webhook новая рассылка
не запускается, ошибка выводится в журнал. Пользовательская Telegram-сессия для
остальных функций приложения работает независимо.

Подписки, ожидающие доставки и недавние дубли сохраняются при перезапуске.
Ошибки сети повторяются с задержкой, `429` учитывает `retry_after`, а при `403`
подписчик отключается. После 10 неудач или ошибки `400` задание удаляется с записью
в журнал. При неопределённом сетевом результате или аварии между отправкой и записью
результата возможна повторная доставка: Telegram Bot API не даёт гарантии exactly-once.
Новые Discord-сообщения во время остановки приложения не загружаются задним числом.

Проверка без внешних подключений: `npm run build:test && node --test dist/tests/telegramBroadcast.test.js`.

## 📁 Структура проекта

- `src/commands/` — Точки входа для slash- и префиксных команд.
- `src/features/` — **Основная бизнес-логика**, сгруппированная по доменам
- `src/services/` — Глобальные сервисы (PostgreSQL, Telegram API).
- `src/utils/` — Переиспользуемые утилиты.
- `src/events/` — Глобальные слушатели событий Discord.

## 🧩 Как добавить новую фичу

1. Создайте папку в `src/features/your-feature/`.
2. Добавьте обработчики событий в `src/events/interactionCreate.ts`.
3. Если нужна новая команда, добавьте её в `src/commands/`.
